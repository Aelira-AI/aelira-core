# Aelira v0.10.0

This release fixes the printed equation alt text problem found after v0.9.13,
repairs equation publication, and removes or repairs most of the runtime
security findings that v0.9.13 disclosed. It adds no database migration.
Automated findings and scores do not establish WCAG conformance.

The version number changes from the 0.9 line because 0.9.1 to 0.9.13 were
published as patch releases but included new features, database migrations and
breaking changes. From 0.10.0 the project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
for 0.x releases, as described under
[Versioning](../../README.md#versioning). This release's breaking changes are
listed under Operator action required.

## Fixed: printed equation alt text

The known issue in the [v0.9.13 notes](v0.9.13.md#known-issue-printed-equation-alt-text)
is fixed
([#693](https://github.com/Aelira-AI/aelira-core/issues/693),
[#694](https://github.com/Aelira-AI/aelira-core/issues/694)). A printed
equation is now staged for review only after a blind second reading agrees with
the first. Equation alt text stays behind the review gate until a person
approves the exact saved file, and it is written only for closed spoken forms.
The saved-file rescan no longer reports a verified equation as undescribed, and
remediation fails closed when review-gated equation content reaches the saved
file without a verified, review-gated fix.

This is still a check on a reading, not a proof that the alt text is right.
Review the alt text of every equation before you publish a remediated PDF.
Long equations that the verifier cannot render are reported with their own
reason and stay manual
([#692](https://github.com/Aelira-AI/aelira-core/issues/692)), and alt text is
not yet generated from verified MathML
([#698](https://github.com/Aelira-AI/aelira-core/issues/698)).

## Changes and limits

- The equation publication gate no longer refuses every PDF that carries a
  verified equation. It refused any failed Matterhorn checkpoint, and
  remediation never sets the PDF/UA identifier, so checkpoint 06-003 always
  failed. It now blocks only failures that remediation adds to the source's
  own, and a refusal is final for the run with a public reason, or HTTP 409 on
  the direct route
  ([#703](https://github.com/Aelira-AI/aelira-core/pull/703),
  [#697](https://github.com/Aelira-AI/aelira-core/issues/697)).
- Transcripts no longer label speakers, because the labels came from a
  pause-and-wording heuristic and not from voice identification
  ([#701](https://github.com/Aelira-AI/aelira-core/pull/701)). Generated alt
  text with line breaks is folded into one line instead of being discarded
  ([#718](https://github.com/Aelira-AI/aelira-core/pull/718)). PowerPoint scans
  read a picture's alt text from where the file keeps it, so decks with
  pictures are no longer capped by a false critical finding
  ([#717](https://github.com/Aelira-AI/aelira-core/pull/717)).
- The dashboard now says "finding no longer detected" where it used to say
  "automated check passed" for a recorded change. The rescan shows a finding is
  gone, not that the change is correct.
- The API image no longer installs Debian's `ffmpeg`. The `ffmpeg` and
  `ffprobe` programs come from the image's own build of FFmpeg 9.0.2, which
  compiles in only the `file` and `pipe` protocols. This removes 110 Debian
  packages and retires 22 advisory dispositions
  ([#748](https://github.com/Aelira-AI/aelira-core/issues/748)).
- The API image replaces Debian's open ImageMagick policy. It now allows only
  PNG, JPEG, EPS and PDF graphics, plus the PAM files Ghostscript produces,
  and refuses MSL and the other script and file-reading coders. LaTeX tools
  run with an empty home directory, and the converter refuses gzip, bzip2, xz
  and zstd input before LaTeXML starts
  ([#749](https://github.com/Aelira-AI/aelira-core/issues/749)).
- PyMuPDF moves from 1.28.2 to 2.0, which bundles MuPDF 1.28.5
  ([#742](https://github.com/Aelira-AI/aelira-core/issues/742)). Pillow moves
  to 13.0.0, pypdf to 6.21.2, `filelock` to 4.2.4 and `setuptools` to 84.2.1.
- The API and development images rebuild Debian's `libxml2`, `libx11` and
  `libxrender` with upstream and Ubuntu security fixes, because Debian has no
  fixed trixie packages. The libxml2 rebuild covers CVE-2026-6653 and six of the
  seven other advisories that the v0.9.13 notes listed as affected. The
  seventh, CVE-2026-86139, is not present in the source Debian ships. See the
  [backport record](../security/debian-backports-0.10.0.md). Debian's own
  `libbrotli1` fix for CVE-2026-111497 (DSA-6582-1) is installed instead of a
  rebuild.
- The scanner runs a hash-pinned Chrome for Testing 156.0.8078.47 instead of
  Playwright's Chromium, which predates that release's security fixes
  ([#746](https://github.com/Aelira-AI/aelira-core/issues/746)). The Pa11y
  runtime moves to Node.js 24.22.1
  ([#745](https://github.com/Aelira-AI/aelira-core/issues/745)). Playwright's
  own driver and test browser in the Python, dashboard and CLI packages are not
  replaced. Chromium-rendered equation images and LaTeX HTML-to-PDF output can
  differ byte for byte from v0.9.13, so compare renders within one release.
- The `certifi` bundle and pip's vendored copy no longer trust `emSign ECC Root
  CA - G3`, whose intermediate certificate authorities have compromised keys
  ([GHSA-6q48-6c7w-9gw2](https://github.com/advisories/GHSA-6q48-6c7w-9gw2)),
  and Node.js 24.22.1's root store no longer includes it
  ([#723](https://github.com/Aelira-AI/aelira-core/issues/723),
  [#725](https://github.com/Aelira-AI/aelira-core/issues/725),
  [#726](https://github.com/Aelira-AI/aelira-core/issues/726)).
- The command line now reports what the API returns. Document scans printed
  `File: Unknown` with no score or counts, and `scan web` and `scan watch`
  read the acknowledgement of a queued scan as its result. They now read the
  scan detail and wait for each scan to finish, and `scan web --batch` sends
  the URL list the API accepts
  ([#772](https://github.com/Aelira-AI/aelira-core/issues/772),
  [#775](https://github.com/Aelira-AI/aelira-core/issues/775)).
  `aelira interactive` no longer clears the terminal and can skip its
  decorative logo, which screen readers read character by character
  ([#770](https://github.com/Aelira-AI/aelira-core/issues/770)). Two changes
  can break scripts: `scan web --format json` returns the finished scan
  detail, and the `aelira export` date column is now `date_utc`.
- The API image build falls back to the zlib release asset when zlib.net
  refuses, still checked against the pinned SHA-256
  ([#707](https://github.com/Aelira-AI/aelira-core/pull/707),
  [#706](https://github.com/Aelira-AI/aelira-core/issues/706)).

See the [changelog](../../CHANGELOG.md) for the other dependency, dashboard
and operational changes and their issue links.

## Known limits and open security items

These findings are disclosed, not resolved, in this release. Disclosure is not
a gate result.

- **libX11, MEDIUM.** CVE-2026-94283, CVE-2026-94284 and CVE-2026-94285 are
  outside the HIGH and CRITICAL gate. They are fixed in the rebuilt `libx11`
  (`2:1.8.12-1+aelira1`) with the upstream libX11 1.8.14 commits, but Debian's
  tracker has no fixed trixie version, so the image scanner still reports them.
  CVE-2026-94285 has a behavioural control that fails on the unpatched code.
  CVE-2026-94283 and CVE-2026-94284 need a malicious X Input Method server and
  are covered by patch application and source review only. The image runs no X
  server, and none of the three was shown to be reachable from user input
  ([#605](https://github.com/Aelira-AI/aelira-core/issues/605),
  [#739](https://github.com/Aelira-AI/aelira-core/issues/739)).
- **PDFium in `pypdfium2`.** `pypdfium2` 5.14.0 is the newest release and
  bundles PDFium 156.0.8076.0, which is before the fix for CVE-2026-113022
  (PDFium memory corruption). No release with a fixed PDFium exists. Uploaded
  PDFs reach it through OCRmyPDF's default rasterizer. Forcing the Ghostscript
  rasterizer would change OCR input and needs its own decision
  ([#747](https://github.com/Aelira-AI/aelira-core/issues/747)).
- **MuPDF double free.** PyMuPDF 2.0 does not fix CVE-2026-112036, a double
  free in MuPDF's `free_char_list`. It is reachable only for a PDF whose
  signature fields carry `/Lock` dictionaries and is rated 4.3. The FreeType
  and MuJS versions inside the MuPDF 1.28.5 build were not verified, so their
  advisories are not marked fixed
  ([#755](https://github.com/Aelira-AI/aelira-core/issues/755)).
- **ImageMagick slowdown.** CVE-2026-106576, a slow rational conversion when an
  image with a crafted XMP profile is written, is affected. LaTeXML can rewrite
  submitted PNG and JPEG graphics, so a document can cause a denial of service
  bounded by the tool timeout. No policy rule covers embedded profiles. The
  fix is a rebuild of ImageMagick
  ([#750](https://github.com/Aelira-AI/aelira-core/issues/750)).
- **Pa11y and zod.** The Pa11y runtime forces zod to 4.6.7 to clear
  GHSA-mrhx-c7xc-m3w5, which has no zod 3 fix. Pa11y 9.0.1's `chromium-bidi` 14
  was written for zod 3, and under zod 4 its validation of invalid input throws
  a `TypeError` instead of a BiDi error. Pa11y drives Chrome over the Chrome
  DevTools Protocol, which `config/pa11y.json` now pins, so `chromium-bidi` is
  not loaded during scans, and the image build checks that. The clean fix is
  Pa11y 10
  ([#786](https://github.com/Aelira-AI/aelira-core/issues/786)). See the
  [override record](../security/pa11y-zod-override-0.10.0.md).
- **Development image.** The development and quickstart images keep pip
  26.2.2, whose wheel vendors `setuptools` 70.3.0 and other pure-Python
  dependencies. The fixes above apply to the application's own packages, not to
  pip's bundled copies, and production images carry no pip. Broader dependency
  work stays open under
  [#578](https://github.com/Aelira-AI/aelira-core/issues/578).
- **Chromium.** The scanner's browser is the pinned Chrome for Testing
  156.0.8078.47. A later Chrome stable release is not included. Move the pin
  in `scripts/chrome-for-testing.json` to take a newer build.
- The other disclosures in the
  [advisory record](../security/known-unfixed-advisories-0.9.12.md) still
  apply, and the broader libxml2, embedded-library and database-driver
  assessments remain open
  ([#579](https://github.com/Aelira-AI/aelira-core/issues/579),
  [#583](https://github.com/Aelira-AI/aelira-core/issues/583),
  [#588](https://github.com/Aelira-AI/aelira-core/issues/588)).

## Operator action required

This release contains no database migration. The single Alembic head is still
`20261020_media_captions`, after `20261018_media_truth`,
`20261017_canvas_scope` and the v0.9.12 head `20260928_pdf_edit_pub`.

1. Before deploying, pause new intake and review/remediation writers. Drain
   active jobs, stop API and worker, and take a verified **coordinated backup**
   of PostgreSQL, uploads, managed report/remediation artifacts, and matching
   private configuration and encryption keys. Include separately configured
   artifact storage and verify a restore path.
2. Pull the exact approved `linux/amd64` or `linux/arm64` API and dashboard
   images, or build both from the **same release** revision. Run
   `alembic upgrade head` explicitly with the matching API image, confirm the
   head is still `20261020_media_captions`, then deploy API, worker and
   dashboard together. Check API and worker readiness and queue progress
   before reopening intake.
3. The API image no longer contains Debian's `ffmpeg` package, and its
   ImageMagick policy refuses every format except PNG, JPEG, EPS and PDF. Check
   any tooling that ran Debian's `ffmpeg` inside the API image, and any custom
   LaTeX project that relies on another graphics format, before upgrading.
4. Recheck source identity, remaining findings and the exact saved output.
   A working file requires separate human approval before publication or
   external writebacks. Unsafe or unsupported output is withheld.

A rollback requires quiescing writers and restoring the matching
**pre-upgrade database**, uploads, artifacts, configuration and encryption keys
with the previous API, worker and dashboard images. Local activity after that
backup is lost; reconcile external writebacks separately. Follow the
[upgrade and recovery procedure](../deployment/upgrade-recovery-rehearsal.md)
and the [v0.9.12 operator notice](v0.9.12.md#operator-action-required).

## Publication integrity

The [release workflow](../RELEASE_INTEGRITY.md) requires this checked-in body
to be consumed verbatim. Publication requires a **signed annotated tag** with a
**GitHub-verified** signature, a successful `ci.yml` push run for the exact
tagged commit on the default branch, and approval through the protected `release` environment.
It must build and verify native `linux/amd64` and
`linux/arm64` API/dashboard images, signed image provenance and signatures,
the CLI through npm trusted publishing, and a seven-file SBOM bundle (three
dependency CycloneDX files and four image SPDX files). The release safety
scan, reviewed vulnerability dispositions and all exact-artifact gates still
apply. Check the workflow result and published artifacts before upgrading.
