# Aelira v0.9.13 — draft

This is a provisional maintenance release note for changes merged after
v0.9.12. It is not a deployment instruction or a statement that v0.9.13 has
passed publication gates. Automated findings and scores do not establish WCAG
conformance. The [v0.9.12 notes](v0.9.12.md) remain the baseline for review,
backup and recovery requirements.

## Changes already on main

- PDF, DOCX and PPTX image remediation now leaves a description unresolved for
  human review when the image's own pixels cannot be analysed. This closes the
  text-only fallback that remained in those remediators despite the broader
  v0.9.12 claim ([#637](https://github.com/Aelira-AI/aelira-core/pull/637),
  [#636](https://github.com/Aelira-AI/aelira-core/issues/636)).
- The API image builds `psycopg2-binary` 2.9.13 from verified source against
  Debian's libpq. It builds Pillow 12.3.0 with libtiff 4.7.2 instead of the
  older wheel copy, retains Raqm text shaping, and omits the unused `pi_heif`
  package and its bundled libraries. Final-image checks and native runtime
  exercises cover these choices ([#641](https://github.com/Aelira-AI/aelira-core/pull/641),
  [#660](https://github.com/Aelira-AI/aelira-core/pull/660),
  [#583](https://github.com/Aelira-AI/aelira-core/issues/583)).
- Both native final images passed PostgreSQL 16 queries, Unicode/JSON,
  transaction recovery, COPY and pooling over verified TLS 1.3, with wrong-host
  and untrusted-CA refusals. Receipts verify the installed driver's RECORD
  hashes and identify the loaded dependency closure by path, hash, binary
  package and source package version. The probe, verifier and canonical pins
  are bound to their actual runtime hashes. Failure controls verify
  owned-fixture cleanup; broader database-library advisory acceptance remains open
  ([#674](https://github.com/Aelira-AI/aelira-core/pull/674),
  [#680](https://github.com/Aelira-AI/aelira-core/pull/680),
  [#588](https://github.com/Aelira-AI/aelira-core/issues/588)).
- Unused `libxml2-utils` and `xdg-utils` are absent from the API image, with
  build and CI checks for their packages and commands. Libraries still used by
  runtime tools remain installed ([#659](https://github.com/Aelira-AI/aelira-core/pull/659)).
- PyAV 18.1.0 is built against hash-verified FFmpeg 9.0.2 shared libraries
  instead of its published wheel's private stack. Both native architectures
  passed reproducible builds, native binding checks, WAV decoding and real
  transcription controls. This covers the transcription WAV consumer;
  the system FFmpeg CLI and complete advisory assessment retain separate gates
  ([#669](https://github.com/Aelira-AI/aelira-core/pull/669),
  [#583](https://github.com/Aelira-AI/aelira-core/issues/583)).
- OpenCV 5.0.0.93 is built from verified source against the shared FFmpeg
  9.0.2 prefix, replacing its published wheel's private media and TLS stack.
  Both native production images and quickstarts passed seven codec families,
  real scene boundaries, single-scene and zero-frame controls, native linkage,
  image-layer and compatibility checks. A scene result is refused when no
  frames decode. Optional OpenCV image backends are disabled; built-in BMP
  and support libraries remain inventoried. The quickstart source-builds its
  five native Python packages and retains pinned pip with a checked vendor
  inventory; findings in those bundled pure-Python dependencies remain open
  ([#675](https://github.com/Aelira-AI/aelira-core/pull/675),
  [#578](https://github.com/Aelira-AI/aelira-core/issues/578),
  [#583](https://github.com/Aelira-AI/aelira-core/issues/583)).
- Python 3.14.8 keeps the official interpreter and rebuilds its matched
  `pyexpat` and `_elementtree` modules from verified source against Debian
  Expat 2.9.0. Both native full images passed layer/runtime matching,
  document consumers, quickstarts and reproducible builds. The older bundled
  modules are excluded from shipped layers; separate advisory and scanner
  gates remain open
  ([#671](https://github.com/Aelira-AI/aelira-core/pull/671),
  [#589](https://github.com/Aelira-AI/aelira-core/issues/589)).
- Hugging Face Hub is 2.2.0 and Tokenizers is 0.23.3. The built-image checks
  exercise a real faster-whisper model download, transcription and cached
  offline load on both architectures ([#643](https://github.com/Aelira-AI/aelira-core/pull/643)).
- The reviewed CLI dependency group updates five packages and repairs its
  installation lockfile. The dashboard group updates eight packages. The
  Python group aligns Pydantic with its required core version and updates
  selected native-fixture and font-corpus pins; SoupSieve's selector consumers
  and fixture pins are verified together. All four groups passed their
  reviewed-head CI before merging. These dependency updates do not close the
  broader embedded-library assessment
  ([#652](https://github.com/Aelira-AI/aelira-core/pull/652),
  [#653](https://github.com/Aelira-AI/aelira-core/pull/653),

- Dashboard fixes cover dialog focus and focus return, route announcements and
  titles, errors, notifications, control names and contrast. The new synthetic
  dashboard regression suite does not replace screen-reader testing
  ([#656](https://github.com/Aelira-AI/aelira-core/pull/656),
  [#376](https://github.com/Aelira-AI/aelira-core/issues/376)).
- For local PPTX uploads, a reviewer can submit a complete, source-hash-bound
  order of supported slide shapes through the API. The queued repair verifies
  the saved order and package preservation before offering a working file.
  Unsupported shapes, unsafe stacking changes, stale or incomplete decisions,
  and cloud/LMS-backed order requests are refused. Accepted order requests are
  reported separately from original scan findings; they do not establish the

  [#373](https://github.com/Aelira-AI/aelira-core/issues/373)).
- Real dashboard CI journeys cover supported document, website, media and
  Canvas paths. Canvas file scans retain a verified source hash, and document
  fixes and working-file publication receive separate review. The shared
  synthetic Canvas course is serialized across CI runs. The new
  `20261017_canvas_scope` migration preserves Canvas identity across courses
  and content types while retaining non-Canvas uniqueness. The credentialed
  Canvas journey and both native image jobs passed; expanded failure paths

  [journey limits](../testing/user-journey-suite.md),
  [#375](https://github.com/Aelira-AI/aelira-core/issues/375)).
- The lxml source build uses zlib's permanent release archive; LaTeXML's
  portable control waits for container readiness and reports bounded failure
  reasons instead of depending on a fixed startup delay
  ([#639](https://github.com/Aelira-AI/aelira-core/pull/639),
  [#642](https://github.com/Aelira-AI/aelira-core/pull/642)).

  exercise is not final combined-artifact or amd64 acceptance
  ([#664](https://github.com/Aelira-AI/aelira-core/pull/664),
  [rehearsal limits](../deployment/upgrade-recovery-rehearsal.md)).
- Optional native CI retention preserves the exact tested API and dashboard
  images for both architectures. The reviewed change passed ordinary and
  retention-enabled CI; all four downloaded bundles passed artifact-digest,
  OCI and source/workflow identity checks. All four bundles predate merged
  [#675](https://github.com/Aelira-AI/aelira-core/pull/675) and
  [#680](https://github.com/Aelira-AI/aelira-core/pull/680), as well as the

## Operator action if a candidate is approved

Preserve the [v0.9.12 upgrade and recovery procedure](v0.9.12.md#operator-action-required):
pause intake and writers, drain jobs, stop API and worker, then take and verify
a coordinated backup of PostgreSQL, uploads, managed artifacts, private
configuration and encryption keys. Upgrade the database explicitly with the
matching API image, confirm its single Alembic head, and deploy API, worker and
dashboard from one approved revision. Reopen intake only after readiness and
queue checks. Review saved outputs before publication; a working file is not
approval.

The merged [Canvas identity change](https://github.com/Aelira-AI/aelira-core/pull/646)
sets the migration head to `20261017_canvas_scope`. It changes Canvas cloud-file
uniqueness. Downgrade refuses when the older uniqueness rule cannot represent
stored valid Canvas identities. Do not delete or rewrite legitimate records to
force a downgrade. Keep the current schema, or recover from the documented
matched database/files backup with the previous application images; any
alternate reconciliation needs its own reviewed plan. Rescan older cloud scans
without a verified source hash before relying on remediation or approval. The
final migration head and these steps must be checked against the actual merged
candidate, then exercised with its matching database and file backup. Recovery
to an older version requires restoring that matched backup and application
images together; external writebacks need separate reconciliation
([#646](https://github.com/Aelira-AI/aelira-core/pull/646),
[recovery procedure](../deployment/upgrade-recovery-rehearsal.md)).

## Publication integrity

Retain the [release integrity gates](../RELEASE_INTEGRITY.md) and the signed-tag,
exact-commit CI, native image, provenance, CLI and SBOM requirements described

upgrade/recovery, security inventory, platform and provider checks against the
final candidate. The arm64 control receipt and work on individual pending PRs
do not establish final v0.9.13 artifact acceptance
([#377](https://github.com/Aelira-AI/aelira-core/issues/377),
[rehearsal limits](../deployment/upgrade-recovery-rehearsal.md)).
