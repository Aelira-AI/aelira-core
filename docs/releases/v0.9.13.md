# Aelira v0.9.13

These notes describe the 0.9.13 combined-source release candidate as of
2026-10-19. The candidate is represented by open draft
[#682](https://github.com/Aelira-AI/aelira-core/pull/682). No v0.9.13 tag,
published image, npm package or release artifact is established by the
evidence below.
Automated findings and scores do not establish WCAG conformance.

## Changes and limits

- PDF, DOCX and PPTX remediation leaves image descriptions unresolved when
  the source pixels cannot be analysed. This corrects the broader v0.9.12
  claim that all text-only fallbacks were removed
  ([#637](https://github.com/Aelira-AI/aelira-core/pull/637)).
- Local PPTX reviewers can submit a complete source-bound shape order through
  the API. The queued repair verifies package preservation and offers a
  working file for review. Unsupported, stale, incomplete, unsafe and
  cloud-backed order requests are refused. This does not establish authorial
  intent or PowerPoint and assistive-technology acceptance
  ([#662](https://github.com/Aelira-AI/aelira-core/pull/662),
  [#373](https://github.com/Aelira-AI/aelira-core/issues/373)).
- Canvas file scans retain verified source identity. The
  `20261017_canvas_scope` migration allows valid Canvas items with the same
  native ID in different courses or content types, while preserving other
  providers' uniqueness. Synthetic dashboard journeys cover documents, web,
  media and Canvas; broader user and provider journeys remain open
  ([#646](https://github.com/Aelira-AI/aelira-core/pull/646)).
- The API image source-builds psycopg2 against Debian libpq, Pillow against
  libtiff 4.7.2, and PyAV and OpenCV against shared FFmpeg 9.0.2. It removes
  unused `pi_heif`, `libxml2-utils` and `xdg-utils`, and rebuilds Python's
  matched Expat modules against Debian Expat 2.9.0. Hugging Face Hub 2.2.0
  and Tokenizers 0.23.3 retain a verified model download, transcription and
  cached offline load. Native checks cover these bounded consumers on both
  architectures; broader embedded-library acceptance is still open
  ([#583](https://github.com/Aelira-AI/aelira-core/issues/583),
  [#588](https://github.com/Aelira-AI/aelira-core/issues/588),
  [#589](https://github.com/Aelira-AI/aelira-core/issues/589)).
- Four merged dependency groups update five CLI packages and repair its
  installation lockfile, update eight dashboard packages, align Pydantic with
  its required core version, and reconcile selected native-fixture and
  font-corpus pins with SoupSieve selector consumers. Each group passed CI at
  its reviewed head before merging
  ([#652](https://github.com/Aelira-AI/aelira-core/pull/652),
  [#653](https://github.com/Aelira-AI/aelira-core/pull/653),
  [#654](https://github.com/Aelira-AI/aelira-core/pull/654),
  [#655](https://github.com/Aelira-AI/aelira-core/pull/655)).
  Their coordination and release-note inclusion are tracked in
  [#665](https://github.com/Aelira-AI/aelira-core/issues/665).
- Dashboard changes improve dialog focus and return, route announcements,
  errors, notifications, control names and contrast. The synthetic regression
  suite does not replace screen-reader acceptance
  ([#656](https://github.com/Aelira-AI/aelira-core/pull/656),
  [#376](https://github.com/Aelira-AI/aelira-core/issues/376)).
- Merged [#640](https://github.com/Aelira-AI/aelira-core/pull/640) rebuilds
  Debian libxml2 with the maintained CVE-2026-6653 patch. Native checks
  verify package and loaded-library identity, relevant consumers and image
  layers. Seven other libxml2 advisories remain affected and disclosed in the
  [advisory record](../security/known-unfixed-advisories-0.9.12.md); the
  [backport assessment](../security/libxml2-6653-backport-0.9.13.md) states
  its narrower disposition. This repair does not close every advisory gate.
- Open [#681](https://github.com/Aelira-AI/aelira-core/pull/681) contains the
  media assessment change.
  Unmeasured video remains unassessed without a safety verdict or overall
  compliance score. Mixed Canvas and Brightspace averages withhold a numeric
  value when any scanned member is unassessed; never-scanned items remain
  excluded and measured zero remains zero. Canvas shows a linked null-score
  scan as “Unassessed” and content without a linked scan as “Not scanned”.
  Draft [#682](https://github.com/Aelira-AI/aelira-core/pull/682) adds the
  completed null-score Brightspace row label “Unassessed”. Matching final-image
  and live-provider checks for the combined candidate remain pending.

See the [changelog](../../CHANGELOG.md) for the other dependency, dashboard and
operational changes and their issue links.

## Operator action required

This candidate contains a database migration. The single Alembic head in the
combined source is `20261018_media_truth`, after `20261017_canvas_scope` and
the v0.9.12 head `20260928_pdf_edit_pub`. The native-only mainline remains at
the Canvas head until the media change merges. Check the actual approved
candidate's migration chain before upgrading.

1. Before deploying, pause new intake and review/remediation writers. Drain
   active jobs, stop API and worker, and take a verified **coordinated backup**
   of PostgreSQL, uploads, managed report/remediation artifacts, and matching
   private configuration and encryption keys. Include separately configured
   artifact storage and verify a restore path.
2. Pull the exact approved `linux/amd64` or `linux/arm64` API and dashboard
   images, or build both from the **same release** revision. Run
   `alembic upgrade head` explicitly with the matching API image, confirm the
   single head, then deploy API, worker and dashboard together. Check API and
   worker readiness and queue progress before reopening intake.
3. Recheck source identity, remaining findings and the exact saved output.
   A working file requires separate human approval before publication or
   external writebacks. Unsafe or unsupported output is withheld.

Do not force a Canvas downgrade by deleting or rewriting legitimate items
that share a native ID across courses or content types. A rollback requires
quiescing writers and restoring the matching **pre-upgrade database**,
uploads, artifacts, configuration and encryption keys with the previous API,
worker and dashboard images. Local activity after that backup is lost;
reconcile external writebacks separately. Follow the
[upgrade and recovery procedure](../deployment/upgrade-recovery-rehearsal.md)
and the [v0.9.12 operator notice](v0.9.12.md#operator-action-required).

## Publication integrity

The [release workflow](../RELEASE_INTEGRITY.md) requires this checked-in body
to be consumed verbatim. Publication requires a **signed annotated tag** with a
**GitHub-verified** signature, a successful `ci.yml` push run for the exact
tagged commit on the default branch, and approval through the protected `release` environment.
It must build and verify native `linux/amd64` and
`linux/arm64` API/dashboard images, signed image provenance and signatures,
the CLI through npm trusted publishing, and a seven-file SBOM bundle (three
dependency CycloneDX files and four image SPDX files). The release safety
scan, reviewed vulnerability dispositions and all exact-artifact gates still
apply. Check the workflow result and published artifacts before upgrading.
