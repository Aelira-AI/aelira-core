# Aelira v0.13.0

This minor release adds WebAuthn passkey sign-in and authenticator-app (TOTP)
multi-factor authentication to the dashboard, and makes the compliance score
show the work behind it. Documents whose score was withheld by a false
structure cycle now score, a score held at the critical-finding cap now says
what holds it, heading-scan refusals reach the reviewer in plain words, and
the remaining caption, table-order, alt-text provenance and CLI integration
defects are fixed. The supply chain tightens with pinned download digests,
two Debian advisory dispositions and four package upgrades. The release adds
two database migrations and changes what a scan returns for documents whose
score was previously withheld. Automated findings and scores do not establish
WCAG conformance.

It is a minor release under [Versioning](../../README.md#versioning): it
carries new features, fixes and security updates. Deployments upgrading from
0.12.1 or earlier must also follow the [v0.12.0 operator
steps](v0.12.0.md#operator-action-required), whose upload behaviour changes
still apply, and deployments upgrading from 0.10.0 or earlier the [v0.11.0
operator steps](v0.11.0.md#operator-action-required).

## New features

- **Passkey sign-in**
  ([#905](https://github.com/Aelira-AI/aelira-core/issues/905),
  [#911](https://github.com/Aelira-AI/aelira-core/issues/911)). Dashboard
  users can register WebAuthn passkeys — device biometrics and hardware
  security keys — and sign in without a password, with email magic-link
  fallback where passkeys are not in use. After login, users with no enrolled
  credential see a one-click enrollment recommendation. A passkey belongs to
  the device and browser it was enrolled on, so keep at least one other
  sign-in path on every account.
- **Authenticator-app multi-factor**
  ([#907](https://github.com/Aelira-AI/aelira-core/issues/907)). Accounts can
  require an RFC 6238 code from a standard authenticator app, with single-use
  backup recovery codes, for institutional and virtual-desktop environments
  where platform passkeys are unavailable.

## Fixes

- **Scores held at the critical cap**
  ([#801](https://github.com/Aelira-AI/aelira-core/issues/801)). Remediation
  results showed an unchanged 49/100 with no reason when unresolved critical
  findings held the score at the critical-finding cap. The result card now
  says the score is held at the cap, names the critical findings still
  holding it, and marks each capped score in the before/after comparison.
- **Identity role maps**
  ([#803](https://github.com/Aelira-AI/aelira-core/issues/803)). Tagged
  tables and headings with identity mappings in a PDF's `/RoleMap`
  (`/Table` mapped to `/Table`, `/H1` mapped to
  `/H1`) were treated as cycles, so required checks failed and scores
  were withheld on valid academic papers and tagged PDFs. Identity mappings
  are now recognized as resolved structure types, and those documents score.
- **Heading-scan bounds and refusal reasons**
  ([#828](https://github.com/Aelira-AI/aelira-core/issues/828),
  [#866](https://github.com/Aelira-AI/aelira-core/issues/866)). Heading
  inventory work on PDFs with many candidate targets is bounded by cached
  per-page line extraction and a match-work cap, so workers are no longer
  starved. When the scan still refuses — an empty or unbound heading, an
  invalid parent relation, an unsupported role map — strict scans complete and
  the refusal surfaces to the reviewer as plain-words review requirements
  naming what to inspect. A refused scan leaves the heading structure
  unverified; the refusal is a reviewer cue, not a pass.
- **Reading order of wrapped table cells**
  ([#829](https://github.com/Aelira-AI/aelira-core/issues/829)). The regional
  reading-order planner only refused an ambiguous matrix when every atom was
  a single line, which let multi-line wrapped cells plan column-by-column and
  reorder tagged prose back into columns. A row-alignment guard with
  tolerance across arbitrary line counts now refuses column reordering when
  column top edges align within half a line height. Tables that previously
  received a column-by-column reorder now fail closed; that is intended.
- **Alt-text provenance**
  ([#734](https://github.com/Aelira-AI/aelira-core/issues/734),
  [#735](https://github.com/Aelira-AI/aelira-core/issues/735)). PDF alt-text
  fixes recorded the configured default model instead of the provider and
  model that answered, and the fixed-issue record omitted `provider_used`.
  The bounded identity of the answering provider and model is now recorded,
  falling back to `"unknown"` when no identity is provided, and a workspace
  with no active vision provider now reports "Alt-text AI provider
  unavailable" instead of a generic no-usable-description message.
- **Generated WebVTT captions**
  ([#818](https://github.com/Aelira-AI/aelira-core/issues/818)).
  Speech-to-text engines commonly produce zero-length segments and trailing
  cues that overrun media duration, which made strict structural verification
  reject the file. Caption generation now drops zero-length cues, drops cues
  starting at or after media duration, and clamps cue ends to the media
  duration before writing.
- **H1 finding category**
  ([#887](https://github.com/Aelira-AI/aelira-core/issues/887)). PDF findings
  for "Document should start with H1 heading" now record the `heading`
  category and `first_heading_not_h1` issue type, aligning with the
  review and publication pipeline. Redundant synthetic HTML language and
  title checks were removed in favour of the authoritative PDF structure
  checks, and review-only and unextractable findings remain exempt from
  automatic remediation. The remaining PDF findings whose fields classify as
  Other, including the AI alt text quality review, keep no category until
  their remediation category is decided.
- **CLI integration parity**
  ([#762](https://github.com/Aelira-AI/aelira-core/issues/762)).
  `aelira integrations connect blackboard` and `connect moodle`
  failed API request model validation because `department_id` was not
  sent, and the Blackboard callback path was misconfigured. Connect now sends
  the configured or specified department, uses `/blackboard/oauth/callback`
  as the redirect URI, and avoids prompting in non-interactive environments.
  `aelira integrations sync` now sends the required `provider` and
  `folder_ids` parameters, auto-resolving active folders when
  `--folder-ids` is omitted, and handles the single-job API response.
- **Native test job timeouts**
  ([#834](https://github.com/Aelira-AI/aelira-core/issues/834)). The cJSON
  native package job intermittently failed during installed-consumers
  validation when subprocess commands timed out on loaded shared runners.
  Subprocess timeouts for dpkg-deb and symbol extraction are raised to 120
  seconds with exact step attribution on timeout.

## Security

- **Pinned digests in native test fetches**
  ([#839](https://github.com/Aelira-AI/aelira-core/issues/839)). The native
  test fetchers for Pillow, consumer wheels and the Python consumer fixture
  verify expected SHA-256 digests instead of trusting reported PyPI digests.
- **Debian sqlite advisories and TIFF fetch**
  ([#924](https://github.com/Aelira-AI/aelira-core/issues/924)). Debian 13
  `libsqlite3-0` advisories CVE-2026-119373 and CVE-2026-119586 are
  dispositioned with VEX justifications, and the TIFF native package
  download is hardened with retry flags.
- **minimatch 11.0.3**
  ([#922](https://github.com/Aelira-AI/aelira-core/issues/922)). The
  transitive `minimatch` upgrades to 11.0.3 through package overrides in
  the dashboard and the CLI, resolving denial of service via pattern
  amplification (CVE-2026-118764).
- **Package upgrades.** `cbor2` moves to 5.9.0, `pyasn1` to 0.6.5 and
  `pypdf` to 6.21.4 to address known vulnerability disclosures.

## Known limits and open security items

These findings were disclosed in the [v0.10.0
notes](v0.10.0.md#known-limits-and-open-security-items), where each is
described, and remain open unless updated above. Disclosure is not a gate
result.

- libX11 CVE-2026-94283, CVE-2026-94284 and CVE-2026-94285 (MEDIUM) are fixed
  in the rebuilt `libx11`, but the image scanner still reports them
  ([#605](https://github.com/Aelira-AI/aelira-core/issues/605),
  [#739](https://github.com/Aelira-AI/aelira-core/issues/739)).
- PDFium CVE-2026-113022 in `pypdfium2` 5.14.0 has no fixed release
  ([#747](https://github.com/Aelira-AI/aelira-core/issues/747)).
- MuPDF CVE-2026-112036 is not fixed by PyMuPDF 2.0, and the FreeType and MuJS
  versions in its MuPDF build are unverified
  ([#755](https://github.com/Aelira-AI/aelira-core/issues/755)).
- ImageMagick CVE-2026-116149 remains unfixed in Debian `trixie-security`; the
  packed-pixel heap-buffer-overflow path is not exercised by PDF page
  rasterisation and stays bounded by the ImageMagick policy and tool timeout
  ([#750](https://github.com/Aelira-AI/aelira-core/issues/750)).
- The Pa11y runtime still forces zod to 4.6.7 until it moves to Pa11y 10
  ([#786](https://github.com/Aelira-AI/aelira-core/issues/786)).
- The development and quickstart images keep pip 26.2.2, whose wheel vendors
  `setuptools` 70.3.0
  ([#578](https://github.com/Aelira-AI/aelira-core/issues/578)).
- A web scan still fails as a whole when a page loads a required resource
  through an HTTP redirect
  ([#800](https://github.com/Aelira-AI/aelira-core/issues/800)).
- The scanner's browser is still the pinned Chrome for Testing 156.0.8078.47.
  A later Chrome stable release is not included.
- The other disclosures in the
  [advisory record](../security/known-unfixed-advisories-0.9.12.md) still
  apply, and the broader libxml2, embedded-library and database-driver
  assessments remain open
  ([#579](https://github.com/Aelira-AI/aelira-core/issues/579),
  [#583](https://github.com/Aelira-AI/aelira-core/issues/583),
  [#588](https://github.com/Aelira-AI/aelira-core/issues/588)).
- An Office file with more than 10,000 parts (or another zip archive with more
  than 1,000 entries) is rated high as a possible archive attack, and since a
  rebuild cannot change that it is refused
  ([#874](https://github.com/Aelira-AI/aelira-core/issues/874)).
- Code files rated high (HTML, CSS, JavaScript and code archives) have no
  rebuild and are processed as uploaded, in the scanner's browser.
- Passkeys and TOTP are covered by automated ceremony tests; no device matrix
  across physical security keys, platform biometrics and named authenticator
  apps is claimed. A passkey stays bound to the device and browser it was
  enrolled on, and email remains the recovery path when an account loses its
  credentials.
- When the heading scan refuses, the document's heading structure stays
  unverified; the refusal now reaches the reviewer as plain-words review
  requirements ([#866](https://github.com/Aelira-AI/aelira-core/issues/866)).
- Delimiters and the data notice limit, but cannot rule out, a document
  steering what a model writes. Review AI-generated text before publishing
  remediated content.

## Release evidence and open gates

The release workflow builds and verifies the API and dashboard images from the
signed `v0.13.0` tag, and its run and published artifacts are the evidence for
this release. This page does not restate their results, and it does not claim
an upgrade rehearsal from v0.12.2. The same `linux/amd64` and `linux/arm64`
gates apply as for earlier releases, including the Pa11y smoke gate and the
Node.js trust-store check.

Passkey registration, authentication and credential management are covered by
automated tests that run the WebAuthn ceremonies through the API and dashboard
suites, and TOTP enrollment, verification and single-use recovery codes are
covered by automated tests. The score-cap display, identity role-map scoring,
wrapped-cell refusal, caption generation and alt-text provenance changes are
covered by targeted unit and integration tests. This page does not claim a
manual assistive-technology test of these changes.

Final artifact, platform, packed CLI and provider acceptance
([#377](https://github.com/Aelira-AI/aelira-core/issues/377)), expanded user
journeys ([#375](https://github.com/Aelira-AI/aelira-core/issues/375)),
dashboard assistive-technology work
([#376](https://github.com/Aelira-AI/aelira-core/issues/376)) and PowerPoint

## Operator action required

This release adds two database migrations, `20261031_webauthn_passkeys`
then `20261031_totp_mfa` (the new head), after `20261028_webhook_secret`,
`20261020_media_captions`, `20261018_media_truth`,
`20261017_canvas_scope` and the v0.9.12 head `20260928_pdf_edit_pub`.

1. Before deploying, pause new intake and review/remediation writers. Drain
   active jobs, stop API and worker, and take a verified
   **coordinated backup** of PostgreSQL, uploads, managed
   report/remediation artifacts, and matching private
   configuration and encryption keys. Include separately configured
   artifact storage and verify a restore path.
2. Pull the exact approved `linux/amd64` or `linux/arm64` API and dashboard
   images, or build both from the **same release** revision. Run
   `alembic upgrade head` explicitly with the matching API image, confirm the
   head is `20261031_totp_mfa`, then deploy API, worker and dashboard
   together. Check API and worker readiness and queue progress before
   reopening intake.
3. Deployments upgrading from 0.12.1 or earlier must first complete the
   [v0.12.0 operator steps](v0.12.0.md#operator-action-required), and
   deployments upgrading from 0.10.0 or earlier must complete the [v0.11.0
   operator steps](v0.11.0.md#operator-action-required), including creating
   Microsoft webhook subscriptions again.
4. Recheck source identity, remaining findings and the exact saved output. A
   working file requires separate human approval before publication or
   external writebacks. Unsafe or unsupported output is withheld.

A rollback requires quiescing writers and restoring the matching
**pre-upgrade database**, uploads, artifacts, configuration and encryption
keys with the previous API, worker and dashboard images. Passkeys and
authenticator apps enrolled after that backup are lost on restore and the
affected users must enrol again. Local activity after that backup is lost;
reconcile external writebacks separately. Follow the
[upgrade and recovery procedure](../deployment/upgrade-recovery-rehearsal.md)
and the [v0.9.12 operator notice](v0.9.12.md#operator-action-required).

## Publication integrity

The [release workflow](../RELEASE_INTEGRITY.md) requires this checked-in body
to be consumed verbatim. Publication requires a **signed annotated tag** with a
**GitHub-verified** signature, a successful `ci.yml` push run for the exact
tagged commit on the default branch, and approval through the protected `release` environment.
It must build and verify native `linux/amd64` and
`linux/arm64` API/dashboard images, signed image provenance and signatures,
the CLI through npm trusted publishing, and a seven-file SBOM bundle (three
dependency CycloneDX files and four image SPDX files). The release safety
scan, reviewed vulnerability dispositions and all exact-artifact gates still
apply. Check the workflow result and published artifacts before upgrading.
