# Critical route coverage

This matrix tracks the backend route contracts in [#35](https://github.com/Aelira-AI/aelira-core/issues/35). It describes the assertions and fixture boundaries in the repository, not a universal endpoint-coverage or accessibility claim. Candidate pass counts and coverage come from that revision's [CI evidence](coverage-and-skips.md).

**HTTP + PostgreSQL** means the mounted production router, queries and commits execute against disposable PostgreSQL records. Authentication can still be replaced at its dependency boundary; that does not verify login or middleware. **HTTP + SQLite** proves persisted query/mutation behavior on SQLite. **Mocked route** means database or service calls are replaced. **Service/transport** exercises production helpers or provider adapters without the whole HTTP route. None of these establish a complete browser/LMS user journey; that remains [#375](https://github.com/Aelira-AI/aelira-core/issues/375).

## Account lifecycle and export

[`test_account_routes.py`](../../tests/test_account_routes.py) requires exact success and missing-auth outcomes for POST `/account/deactivate`, `/deletion/request`, `/deletion/confirm`, `/deletion/cancel`, GET `/deletion/status` and `/export`. Two synthetic accounts in one department establish per-user scope. The suite checks persisted deactivation, credential revocation, deletion scheduling/cancellation, expired or invalid codes, exported records and omission of credential material. Query, commit, audit, service-factory and delivery failures have bounded responses; lifecycle commit/audit failures preserve prior account and credential state.

Confirmation-code delivery is awaited. A failed or unavailable mail service returns 502 and retains the stored expiring code for a subsequent request to replace; it does not schedule deletion. Optional notification failure after confirmed scheduling leaves the successful persisted schedule intact. Code storage, external delivery and the request audit are separate effects, not an atomic delivery transaction. Deactivation, scheduling and cancellation stage their state and audit changes together.

These are HTTP + PostgreSQL contracts with controlled, signature-checked mail and substituted authenticated identity; the required-auth adapter remains active. Per-test outer transactions/savepoints establish same-connection persistence and rollback, not concurrent or cross-connection behavior. Cancellation tests supply an identity: confirmation deactivates the account and revokes normal credentials, so these tests do not establish a reachable recovery login or cancellation browser journey. No real email or live account is used.

## Failure and queue evidence

### Google Workspace file workflows

[`test_google_workspace_e2e.py`](../../tests/test_google_workspace_e2e.py) now contains ordinary, ungated backend integration tests despite its historical filename. It replaces 17 obsolete journey mocks and the permissive file-route checks formerly in `test_google_integration.py`. Exact HTTP results cover file/folder browsing, metadata, download, Docs/Slides/Sheets exports, file/folder scan enqueue, remediation enqueue and department/provider-scoped job status. Real PostgreSQL rows establish credential/file/job ownership and durable queue identities; repeated file scans return the existing deduplicated job ID. Folder scans pass the recursive flag to the production adapter's traversal API.

The fixture supplies authenticated identity and signature-checked provider adapters. Token encryption and refresh-state persistence are real; outbound refresh results are controlled. Export cases also execute the real Office export services through a controlled discovery transport. Missing/inactive connections, foreign resources, invalid input and provider/database/queue/storage failures have exact refusal assertions. Savepoint-backed reloads prove rollback and persisted state on the test connection; they do not establish cross-connection visibility or concurrent execution. Existing OAuth transport, initial webhook safety and canonical adapter DTO suites remain required.

Download responses contain binary bytes and use a temporary directory owned by the route. The route refuses an unexpected returned path and cleans only its own directory. Real-adapter transport cases also verify cleanup of the adapter's separate temporary directory after successful responses, provider failures and HTTP-client close failures. Initial webhook creation has the same cleanup guarantee, with its existing provider/state behavior preserved and signature-checked failure cases. Office exports return response bytes with the matching MIME type; supplying the old `output_path` field returns 422. The legacy `/google/upload` local-path operation returns 501 without inspecting a file or claiming a fabricated upload/job ID. Managed remediation artifact publication remains a separate worker/service workflow; these route tests do not prove provider writeback, produced document quality or a browser journey. Full journey evidence remains #375.

### Shared integration status and webhooks

[`test_integration_status.py`](../../tests/test_integration_status.py) covers GET `/integrations/status`, `/health`, `/health/google`, `/health/microsoft`, `/metrics`, `/metrics/{integration}`, `/webhooks/{provider}` and DELETE `/integrations/{integration}`. Exact contracts exercise all six stored provider profiles, inactive/other-department exclusion, provider-specific queue counts, local disconnect persistence, missing connections, unsupported providers, missing authentication and representative query/commit failures. The connected Moodle regression uses the actual credential profile columns. Provider metrics filter the durable queue's provider field; legacy rows without provider identity are not attributed to a provider. Overall metrics retain all department jobs.

[`test_webhooks.py`](../../tests/test_webhooks.py) replaces the 28 gated legacy cases with current POST `/webhooks/google/subscribe`, `/microsoft/subscribe`, DELETE `/subscriptions/{subscription_id}`, GET `/health`, Microsoft GET/POST validation, and supported Google/Microsoft callback contracts. Persisted subscriptions exercise local deactivation, retries, department scope, missing IDs, required query inputs and commit failures. Supported callback fixtures persist a notification timestamp and one deduplicated pending reconciliation job with exact input; injected enqueue failure preserves the prior timestamp and leaves no job. Malformed Microsoft envelopes have exact refusal assertions. Existing initial-subscription, renewal/identity/retry and controlled provider adapter suites remain complementary and unchanged.

These are HTTP + PostgreSQL contracts with supplied identity. The request database dependency and callback context-manager seam use the same real session and preserve rollback on failure; route commits release savepoints in a rollback-only outer transaction. Reloads establish stored state on that connection, not cross-connection visibility or concurrency. Missing-auth cases restore the actual dependencies. No live provider, worker, browser or credential parsing journey is exercised.

Current limits are explicit: integration health is static liveness, not a provider probe. `total_files_synced` remains the completed-job count alias, not a measured file inventory. Integration webhook status returns an empty placeholder even when subscriptions exist; subscribe endpoints return `not_implemented`. Disconnect deactivates the local credential and leaves subscriptions in place; subscription deletion deactivates only the local row. Neither operation revokes provider tokens or channels. Webhook health reports global active subscription counts. Callback success proves accepted local fixtures and enqueue behavior, not independent validation of provider identity, delivery, retry concurrency or worker completion. The six obsolete mock skips and 28 legacy webhook skips are replaced by required, executing node IDs in the CI policy; full-suite coverage and the separate 41-test worker requirement remain unchanged.

### Alert settings and delivery

[`test_alert_settings_routes.py`](../../tests/test_alert_settings_routes.py) covers GET/PUT `/api/alerts/settings`, GET/POST `/emails`, POST `/emails/add` and `/emails/remove`, DELETE `/emails/{email}`, and POST `/pause` and `/resume`. Exact HTTP assertions check saved preferences and recipient lists, both aliases, duplicate handling, missing recipients, schedule/email validation, missing authentication and ordinary department separation. PostgreSQL reloads verify stored values. The per-test connection uses an outer transaction with savepoints; these tests do not establish cross-connection commit visibility or concurrent updates. Failure cases establish success before injecting a query/commit exception; test cleanup explicitly rolls back the fixture session.

[`test_alert_delivery_routes.py`](../../tests/test_alert_delivery_routes.py) covers POST `/test`, `/send`, the three `/trigger/*` routes and GET `/history`. Identity is supplied, settings use PostgreSQL, and a signature-checked mail service replaces delivery. Assertions verify department recipients, configured dashboard links, supplied issue/period data, disabled/empty-recipient behavior, rejected delivery results, exceptions and partial custom-send counts. Separate cases execute the real scan and weekly renderers through a controlled transport, including unavailable severity versus measured zero. No live mail provider or delivery queue is exercised: these endpoints call the mail service directly.

The prior permissive route assertions in `test_alerts.py` are replaced by these contracts. Its template and compatibility-wrapper checks remain complementary; the mixed-preference filter in `test_email_preferences.py` now queries actual stored users and executes without its old mock-related skip.

Current limits are explicit: there is no defined application recipient cap (a 20-recipient list is tested, not an unlimited guarantee). Pause disables all three flags and resume enables them; there is no timed pause or restoration of prior individual flags. History returns an empty list with an unavailable-tracking message, including after controlled successful delivery. It does not prove stored delivery history, type filtering or pagination. These contracts do not claim administrator-only authorization, a full login journey, provider acceptance or inbox receipt. Follow-up policy or history implementation must be separately specified.

[`test_auth_dependency_failures.py`](../../tests/test_auth_dependency_failures.py) proves successful key-management/validation, quota/department reads, magic-link request/check/verify, session refresh/validate/logout and email-preference contexts before injecting representative collaborator failures. Exact HTTP failures must not report success or expose the fixture exception. Authentication and selected services are controlled; this suite does not prove provider availability. Profile update requests also restore the actual identity dependency to check missing-auth refusal.

[`test_review_failure_routes.py`](../../tests/test_review_failure_routes.py) covers queue/stats/department-summary, document/audit/export/package and deferral/revoke failures. Each database-failure case establishes HTTP success first, injects the query failure, checks unchanged persisted state, then demonstrates recovery. Separate cases check invalid queue filters/pagination, export renderers and package-builder failure. The mutation suite covers flushed writes and request rollback after a commit failure.

[`test_remediation_queue_routes.py`](../../tests/test_remediation_queue_routes.py) connects HTTP enqueue, canonical options, durable job identity/deduplication, status/latest and download mapping using PostgreSQL rows. It also checks missing source/results, invalid options, absent IDs and single/batch queue rejection with rollback. Completed-job output is a seeded, approved artifact fixture: the suite verifies route mapping and exact downloaded bytes, not worker generation or remediation quality.

The artifact suite independently checks a completed scan whose remediation requires manual work: metadata explains the verification blocker and approval is refused without an approval audit. The Canvas route/service contracts use controlled provider responses; the complete worker/provider/browser flow remains #375. Final candidate-wide counts and coverage must still come from the revision's CI run.

### Administrator users and invitations

[`test_admin_user_routes.py`](../../tests/test_admin_user_routes.py) exercises `/admin/users`, user role updates/removal and `/admin/stats` through HTTP and real PostgreSQL queries. It checks active department membership, saved roles/deactivation, transactional role-change audits, nonempty scan statistics, unknown scores, lifecycle/input conflicts and database failure rollback. The real administrator dependency admits supplied session/API-key principals and refuses ordinary faculty and LTI principals. Credential parsing and login are separate evidence.

[`test_admin_invitation_routes.py`](../../tests/test_admin_invitation_routes.py) covers create/list/revoke/resend, exact visible list fields, ordinary foreign-department refusal, missing authentication, invalid input, expired pending rows, duplicate/capacity rules and commit/query failures. Expired invitations are excluded from pending lists/counts and cannot consume capacity or block a replacement invite. Mail uses a signature-checked substitute; success/failure audit records and an awaited result establish the application contract, not live provider acceptance or inbox receipt.

The shared fixture uses per-test PostgreSQL outer transactions and savepoints. Reloads prove database state on that connection; they do not establish cross-connection commit visibility or concurrent user administration. Role changes and their audit records are committed together. Ordinary removal/revoke routes do not gain new audit event types in this change. Existing `/auth` handoff acceptance tests remain complementary evidence.

Invitation rows are saved before delivery. A failed delivery returns HTTP 502 with a plain message instructing the administrator to refresh invitations and retry; a list refresh exposes the saved pending invitation for resend. Resend saves its rotated token and extended expiry before sending, including on delivery failure. Database commit, provider acceptance and audit persistence are not a distributed transaction; this is not a durable mail queue or exactly-once delivery guarantee.

## Maintaining the evidence

Use the disposable database and service setup in [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml). Critical cases belong in [`tests/ci_skip_policy.json`](../../tests/ci_skip_policy.json) as exact required node IDs. They must execute; an environment skip or broad status-code alternative cannot satisfy their contract. Preserve the full-suite coverage floor and exclusions.

When adding a row, name a test that reaches its successful path and the relevant denial/input/failure cases. State every substituted boundary. Report pass/skip counts from the tested revision separately from this source inventory, and retain remaining conditions rather than treating a coverage percentage as endpoint completeness.
