# Microsoft route contracts

[Issue #427](https://github.com/Aelira-AI/aelira-core/issues/427) replaces permissive Microsoft assertions with exact HTTP and persistence contracts. The protected main profile requires every case in [`test_microsoft_file_routes.py`](../../tests/test_microsoft_file_routes.py), [`test_microsoft_365_e2e.py`](../../tests/test_microsoft_365_e2e.py) and the retained OAuth transport tests in [`test_microsoft_integration.py`](../../tests/test_microsoft_integration.py).

The fixture mounts the real router, uses PostgreSQL transactions and supplies a validated session identity. Credential encryption/decryption, OneDrive adapters, provider DTOs, file synchronization, durable enqueue and subscription records execute. Graph HTTP is replaced by a fail-closed `httpx.MockTransport`; entitlement and identity validation are supplied seams. No live Microsoft account or browser participates. The historical `e2e` filename contains server-side route journeys, not a worker or live-provider end-to-end claim.

## Retired assertions and compatibility

The former OneDrive/SharePoint operation classes in `test_microsoft_integration.py` accepted success, authentication failure and missing route responses interchangeably. Their file, scan/remediation, connection and subscription purposes map to the rows above. The OAuth service tests retain their existing names and real controlled HTTP transport.

The 19 `RUN_E2E_TESTS`-gated Microsoft cases used obsolete `/api/microsoft` paths and SDK mocks. File and subscription cases now map to the required route matrix; account/disconnect map to the two persisted journeys; OAuth initiation/exchange/refresh map to retained transport contracts and the persisted refresh case. No unsupported legacy endpoint was added to satisfy a stale test. The `microsoft-mocked-journey-tests` skip allowance is removed.

Existing JSON containers for browse and subscription responses are retained. Binary download now returns file bytes rather than attempting to JSON-encode them. SharePoint scan requests now require prior file tracking and persist the worker-required file binding. Single scan responses add `job_id`; folder scan responses add `job_ids`. Local-path upload returns 501 instead of claiming an upload happened. Subscription creation accepts the drive-root resources and `updated` change type supported by the existing adapter; expiry continues to use that adapter's duration. The existing department-bound webhook notification protocol is unchanged.

## Evidence limits and reconciliation

A database transaction cannot roll back a remote Graph operation. Subscription creation commits an inactive `requesting` intent before calling Graph; renew/delete similarly commit a pending marker before the request. Credential refresh completes before a locked renew/delete lookup, so its commit cannot release the subscription lock before the marker is written; `test_expired_refresh_commits_before_subscription_row_lock` observes the PostgreSQL lock and commit ordering. Failed or interrupted operations conservatively retain that marker, block another route mutation with 409, and prevent the refresh worker from issuing a blind retry. Even a definite provider rejection is retained conservatively for reconciliation. Local files/queue writes, by contrast, roll back within their transaction on the exercised failures.

Initial inactive intents are absent from the active subscription list. A 409 after an uncertain result requires operator reconciliation of the stored intent with the provider; this change does not provide an automated reconciliation UI or prove remote rollback. It also does not prove live callback delivery, live OAuth consent, worker scan/remediation execution, or final artifact publication. The ordinary request tests are not a concurrent subscription race test.

At this revision the Microsoft modules contain 108 required cases: 101 file/queue/subscription cases, five OAuth transport cases and two persisted route journeys. The main policy has 1,551 required cases and 260 permitted skips; the separate 41-case worker requirement and 68% coverage floor are unchanged. These inventory totals describe policy, not a claim that full CI or the complete coverage gate ran locally.
