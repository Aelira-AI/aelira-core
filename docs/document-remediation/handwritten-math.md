# Handwritten math suitability corpus

Issue #223 freezes the input boundary used by the handwritten mathematical
expression recognition work in issue #233. The corpus is intentionally small:
it establishes deterministic policy and regression evidence, not broad claims
about handwriting recognition quality.

## Suitability is not recognition

The classifier answers one question: may this exact crop enter the later HMER
specialist? `eligible` does not mean that the expression was read correctly.
It means only that the crop satisfies the frozen offline pixel policy. HMER
semantics, independent verification, PDF association, and human approval remain
separate requirements in issue #233.

The public dispositions are:

- `eligible` — the later HMER specialist may attempt recognition.
- `human_review` — supported-looking material is ambiguous under the frozen
  boundary and must stay open for a person.
- `unsupported` — the crop lacks the bounded handwritten-math structure needed
  by this policy and must not enter HMER.

Low contrast, strike-throughs, annotations, and multiple lines always require
human review in this corpus. Diagram-only content, dense unsupported marks,
ordinary non-math handwriting, and visually similar non-math content are
unsupported. Every HMER result in issue #233 will also always require human review
before artifact availability, including crops that were eligible here.

## Provenance and limits

Every checked-in image is generated by
`scripts/generate_handwritten_math_corpus.py` from project-authored synthetic
strokes and distributed under `AGPL-3.0-only`. The manifest binds each fixture's
author, generation method, source class, category, expected disposition, and
SHA-256. Images carry no metadata. The corpus contains no downloaded material,
student work, customer content, or proprietary source.

This corpus does not represent non-Latin notation, real classroom capture noise,
the full range of motor disabilities, unusual writing implements, all mathematical
scripts, or all combinations of annotations and diagrams. Those gaps prevent a
general handwriting-quality claim. Additions require new project-owned or clearly
redistributable fixtures, a new versioned policy when thresholds change, and a
review of the frozen false-positive gate.

## Reproduce the corpus and evaluation

Regenerate the corpus into a temporary directory and compare it with the checked-in
bytes:

```bash
python scripts/generate_handwritten_math_corpus.py --output-dir /tmp/aelira-hmer-corpus
```

Run the bounded deterministic CI subset:

```bash
python scripts/evaluate_handwritten_math_corpus.py --subset ci
```

Run the complete offline evaluation:

```bash
python scripts/evaluate_handwritten_math_corpus.py --subset full
```

For a larger model evaluation, capture only the exact typed disposition for every
selected fixture in a `handwritten-math-predictions-v1` JSON file. Bind it to the
reported corpus and policy digests, then evaluate it without retaining provider
prose:

```bash
python scripts/evaluate_handwritten_math_corpus.py --subset full --predictions predictions.json
```

The evaluator exits nonzero when fixture bytes drift, prediction identities are
stale or incomplete, any expected disposition changes, or a non-math negative is
classified as eligible. Prediction-backed reports retain the bounded provider,
model, and canonical prediction-set digest, but no raw provider prose. The frozen
v1 gates are 1,000,000 ppm expected-disposition accuracy and exactly zero eligible
false positives.
