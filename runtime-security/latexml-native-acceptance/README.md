# Native LaTeXML source-component acceptance

This entrypoint is prepared for later root-owned CI integration of issue #600. It uses the exact accepted ten-file generated-runtime recipe, official LaTeXML commit, fixed adapter and Ubuntu 26.04 base. It does not change the compatibility oracle, product behavior, or wider full-application acceptance.

`prepare` runs from a trusted operator checkout. Give an absolute operator repository path, full selected commit and tree OIDs, and `--source-kind public` with an exact `--remote-ref` (for example `refs/heads/main`). Public preparation checks that this ref resolves to the selected commit at the named Aelira origin. `--source-kind synthetic` is only for clearly labeled local Git fixtures; it has no remote-ref or public-source claim. The selected commit must contain this runner, this README and the accepted recipe as regular Git blobs with their exact reviewed bytes. Working-tree and index contents are not package inputs. `prepare` emits a deterministic transport, binding and receipt in a new output directory.

Before transferring code, the operator must take the transport, binding and runner hashes from the trusted preparation receipt, and independently verify the `bootstrap.py` SHA-256 against the selected trusted Git checkout. Transfer the bootstrap separately. Invoke it with literal expected transport, binding, runner, commit, tree, source-kind, operator-repo and (public mode only) remote-ref values. It independently checks the selected Git commit/tree, approved origin, public remote ref when applicable, its own selected bootstrap bytes and the selected archive blobs before extraction. It validates the complete 13-member regular tar closure and accepted recipe hashes before extracting any code. A CI workflow should obtain these expectations from its trusted checkout and selected public Git ref; it must not read expectations from the untrusted archive. After extraction, run `SCRATCH/source/native_acceptance.py run SCRATCH` with the same explicit operator repo/ref/tree/source-kind, `--architecture`, official upstream checkout, frozen native APT input and exact lock SHA-256. The run rechecks exact readable file and directory closure without following aliases, and the selected Git objects and transport before invoking copied recipe code.

The native run checks host, Docker daemon, dependency container and accepted source container architecture. It reauthenticates the Ubuntu archive keyring, four signed native Releases, all signed-hash-bound Packages indexes, unique DEB identities and exact confined file closure before an offline dependency-image build. For AMD64, supply a distinct authenticated native input lock; the reviewed ARM lock cannot serve as an AMD proof. It measures real Perl and Parse::RecDescent bytes inside the immutable dependency image, makes two independent offline Git-object source/runtime packages, accepts the image using the existing recipe, checks installed helper/module/command identity and runs ordinary version, document XML and math controls. Refusal controls follow successful positives.

The run writes private raw logs under `SCRATCH/private` and always attempts a bounded `SCRATCH/status.json`; a failed run keeps its original failure status. `export SCRATCH --out NEW_OUTPUT --operator-repo TRUSTED_REPO --operator-ref COMMIT --operator-tree TREE --source-kind KIND --binding-sha256 BINDING --runner-sha256 RUNNER --architecture ARCH` (plus `--remote-ref REF` in public mode) works only after success and copies seven fixed JSON files after strict nested schemas, fixed generated metadata, literal counts, the exact unique positive-first nineteen-case control contract, independently selected Git/binding/runner identities, architecture and cross-hash checks, then writes a manifest for that exact selected closure. Do not export raw logs or arbitrary files. Keep every failed scratch and its partial output private and unchanged. Do not edit an executing source or replace an earlier transport.

The original full-application smoke still has 17 measured baseline/version differences. A native component positive does not establish full-application, final-runtime, dependency/advisory/all-copy/security, provider/static XML/SVG, public CI, both architectures or closure of #600, #579, #578 or R10. Root owns CI integration, Git, review and disclosure.
