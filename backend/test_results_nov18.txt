## ADDITIONAL INVESTIGATION - AI CODE FIX TIMEOUT ROOT CAUSE

### Code Analysis Findings

1. **Code Generation Flow (web_scanner.py:1455-1577)**
   - Calls Ollama chat API with qwen2.5-coder:7b model
   - Temperature: 0.2 (low for consistency)
   - Tokens: 600 max prediction
   - Has proper try/catch error handling
   - Returns fallback fix if Ollama call fails

2. **Validation Logic (web_scanner.py:1708-1785)**
   - Checks for HTML tags
   - Checks for placeholder text patterns
   - Issue-specific validation (e.g., alt= for images)
   - Returns True/False (no infinite loops)
   - On validation failure, uses fallback fix

3. **Observed Behavior**
   - Scan stuck at 95% for 7+ minutes
   - Ollama receiving requests and responding (200 status codes)
   - Some requests taking 8-36 seconds
   - Log: "[CODE FIX] Validation failed for color-contrast, using fallback"
   - Background process (PID 22) still running

### Hypothesis: Not a Hang, But Very Slow Processing

The code has proper error handling and fallbacks. The issue is likely:

**Performance bottleneck, not a bug:**
- qwen2.5-coder:7b is a large model (7B parameters)
- First inference on cold start: 20-40 seconds
- Subsequent inferences: 8-15 seconds per fix
- If scanning finds many issues (Yale potentially has more than 1), each needs AI generation
- Progress stuck at 95% could mean:
  - Multiple issues being processed sequentially
  - Each taking 15-30s with validation retries
  - Total time: N issues × 20s = could be 5-10 minutes for 20+ issues

**Evidence:**
- No error logs (process would log exceptions)
- Ollama returning 200 OK (successful responses)
- Validation working (returning fallback when needed)
- Progress tracking not updating (poor granularity - only reports "generating fixes" as one step)

### Recommended Actions

**IMMEDIATE - To Unblock Testing:**
1. Kill the stuck scan process (restart API container)
2. Test with smaller model (qwen2:0.5b instead of 7B) for speed
3. Test with generate_code_fixes=false to establish baseline scan times
4. Add timeout to Ollama API calls (e.g., 30s max per fix)

**SHORT TERM - Improve User Experience:**
5. Add more granular progress updates (e.g., "Generating fix 3 of 12...")
6. Add per-fix timeout (skip AI generation after 30s, use fallback)
7. Parallelize AI fix generation (process multiple issues concurrently)
8. Cache AI fixes for identical issues (save repeated API calls)

**MEDIUM TERM - Performance Optimization:**
9. Profile qwen2.5-coder:7b performance on VPS hardware
10. Consider switching to qwen2:0.5b for development/testing

## Research Objective
Find CPU-optimized AI models for accessibility code generation that work on basic hardware (32GB RAM, no GPU) for both our production VPS and open-source users.

## Models Researched

### Qwen 2.5 Coder Family
✅ **1.5B** (986MB) - Downloaded and available
⏳ **3B** (1.9GB) - Downloading
✅ **7B** (4.7GB) - Already available (too slow on CPU)

### Alternative Models
⏳ DeepSeek-Coder 1.3B (776MB) - Downloading
❌ StarCoder2 3B - Not specialized for accessibility
❌ Codestral 22B - Too large for 32GB systems

## Key Findings

### CPU Performance Benchmarks
- **1.5B models:** 10-20 tokens/sec on CPU (15-30s per fix)
- **3B models:** 5-15 tokens/sec on CPU (20-60s per fix)  
- **7B models:** 1-3 tokens/sec on CPU (100-300s per fix) ❌ TOO SLOW

### Accessibility-Specific Insights
- LLMs achieve ~94% success on simple fixes (contrast, semantic HTML)
- Struggle with complex ARIA (pages with ARIA have 41% MORE errors)
- Need strong prompting with WCAG examples
- Semantic HTML preferred over ARIA

## Recommended Strategy

### Hybrid Model Approach
1. **Default:** Qwen2.5-Coder 1.5B (fast, 80% of fixes)
2. **Complex Issues:** Qwen2.5-Coder 3B (critical/serious only)
3. **Fallback:** Template-based fixes (when AI times out/fails)

### Implementation Features
- Automatic model selection based on issue severity
- 15-30s timeout per fix (prevent hanging)
- Caching for identical issues (60-80% reduction)
- Template fallbacks for all common patterns
- Hardware detection (use 7B on GPU if available)
